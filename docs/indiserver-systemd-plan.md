# INDI Server Systemd Plan

Date: 2026-06-15

## Goal

Run the ASI678MC INDI server as a dedicated user systemd service without changing the indi-allsky capture runtime.

This first version is intentionally scoped to one INDI camera:

- camera: ZWO ASI678MC
- driver: `indi_asi_ccd`
- port: `7625`
- socket path: `/tmp/indiserver-modern-admin-7625`
- service: `indiserver-asi678mc.service`

The capture worker should continue to connect to an already-running INDI endpoint. It should not auto-start `indiserver`.

## Files

The helper script is:

```bash
misc/setup_asi678mc_indiserver.sh
```

It creates or updates:

```bash
~/.config/systemd/user/indiserver-asi678mc.service
```

The generated service runs:

```bash
indiserver -v -p 7625 -u /tmp/indiserver-modern-admin-7625 indi_simulator_telescope indi_asi_ccd
```

The service includes:

- `Before=indi-allsky.service`
- `Restart=on-failure`
- `RestartSec=5`
- `WantedBy=default.target`

## Install Or Update

From the repository checkout on the Pi:

```bash
./misc/setup_asi678mc_indiserver.sh
systemctl --user daemon-reload
systemctl --user enable --now indiserver-asi678mc.service
systemctl --user status indiserver-asi678mc.service --no-pager
```

If the service should survive boot before login, make sure user linger is enabled:

```bash
sudo loginctl enable-linger "$USER"
```

The normal setup script already does this for standard installs.

## Verify INDI

Check the service:

```bash
systemctl --user status indiserver-asi678mc.service --no-pager
journalctl --user -u indiserver-asi678mc.service -n 100 --no-pager
```

Check that INDI responds:

```bash
indi_getprop -h localhost -p 7625
```

Expected result:

- no connection refused error
- ASI/ZWO camera properties are listed
- `Telescope Simulator` may also be listed

## Configure indi-allsky For ASI Registration

For a temporary ASI registration run, set the capture config to:

| Setting | Value |
| --- | --- |
| `CAMERA_INTERFACE` | `indi` |
| `INDI_SERVER` | `localhost` |
| `INDI_PORT` | `7625` |
| `INDI_CAMERA_NAME` | exact ASI camera name, if known |

Then start `indi-allsky.service` only long enough for capture startup to connect and create/update the camera DB row.

## Rollback

Stop and disable the dedicated ASI service:

```bash
systemctl --user disable --now indiserver-asi678mc.service
```

Restore the previous indi-allsky capture config for the Camera Module V3 Wide:

- `CAMERA_INTERFACE`: previous `libcamera_*` value, for example `libcamera_imx708`
- `LIBCAMERA.CAMERA_ID`: previous value
- `INDI_SERVER`, `INDI_PORT`, `INDI_CAMERA_NAME`: previous values

Then restart the normal capture service:

```bash
systemctl --user restart indi-allsky.service
```

## Notes For Future Multi-Camera Runtime

This service is intentionally separate from the existing `indiserver.service` generated by `setup.sh`.

For multi-camera runtime, the likely next step is to map each INDI `CaptureProfile` to a dedicated service name and port, for example:

- `indiserver-asi678mc.service` on `7625`
- another future INDI camera on a different port

`CaptureWorker` should remain a consumer of an already-running endpoint. Startup and supervision should stay with systemd or a thin manager that controls systemd units.
